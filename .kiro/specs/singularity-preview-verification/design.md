# Singularity replay verification design

Drive the existing public Showdown traces and presentation code. Put generated layouts and the deliberately dropped hit in the existing presentation test file. Then start the built illustrated game in Chrome through its native Card gallery. Sample visible labels and spell phases, and collect representative frames and a receipt in the ignored artifacts directory. The fixed game engine and art are the reference throughout.

The Kiro workflow builds once, checks the presentation and browser in parallel, then hands the reports to a separate reviewer. Check the working tree against the approved source for runtime and asset changes. Preserve the distinction between generated rules coverage, automated browser evidence and the art owner's visual judgment.
