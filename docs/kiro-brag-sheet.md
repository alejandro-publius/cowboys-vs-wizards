# How we used Kiro on Cowboys vs. Wizards

1. **IDE, CLI and Crew.** Kiro IDE’s Requirements-First spec session turned the attack prototype into a full card match using Fable’s rules and CPU. Kiro CLI ran narrower tasks for card presentation, arena loading and the Mounted Billy import in separate worktrees. A resumed CLI review matched the finished showdown to the opening replay. Kiro Crew’s local preview ran 2,000 CPU matches to measure a proposed Skeleton stat change. [Build log](kiro-build-log.md) · [Static preflight](evidence/kiro-submission-preflight.md) · [Crew preview](evidence/kiro-card-pipeline.md#kiro-crew-balance-preview)
2. **Custom agents.** The `duel-presenter` profile carries the game’s steering and starts with focused tests. It helped Kiro correct the card’s projected landing target and fall back to the lane button when the board position is invalid. Kiro reused the same profile to fit the mounted troop. [Agent profile](../.kiro/agents/duel-presenter.json) · [Build log](kiro-build-log.md)
3. **Agent hooks.** A fresh `duel-presenter` session on November 16 triggered the SessionStart hook. Its receipt recorded 19 passing presenter, controller and card model tests. Its current output path is `.artifacts/kiro/ui-hook.txt`, so starting a session leaves the tracked files clean. Kiro’s card save triggered the other hook, regenerated the catalog and passed all three registration checks. [SessionStart receipt](evidence/kiro-ui-hook.txt) · [Card save trial](evidence/kiro-card-pipeline.md#card-registration)
4. **Spec-driven development.** Kiro structured the Orb Duel around requirements, design and ten implementation tasks. The spec exposed a restart case before implementation. Reusing a seed resets the engine revision, so an old scheduled action can appear current. Kiro’s controller tracks a separate match epoch to cancel those actions. The spec also required both attackers to finish a simultaneous clash and tied that requirement to a seeded property. [Orb Duel spec](../.kiro/specs/orb-duel/requirements.md) · [Design decisions](kiro-build-log.md)
5. **Steering.** The always-on `build-evidence` guidance standardized the spec closeout’s seed, verification and attribution record. The presentation steering loads for the match, renderer, UI, art and replay paths. It tells an agent to use the rules engine’s accepted values for orbs and to check restart cancellation when changing playback. [Evidence steering](../.kiro/steering/build-evidence.md) · [Presentation steering](../.kiro/steering/duel-iteration.md)
6. **MCP.** Kiro called the workspace’s read-only `inspect_duel_replay` tool to compare a receipt with the exact built HTML. A matching seed-0 web build passed. An earlier run paired a clean receipt with older standalone HTML and returned `stale` even though the receipt still listed eight passing checks. [Review runs](evidence/kiro-overnight.md#power-and-mcp) · [Static preflight](evidence/kiro-submission-preflight.md)
7. **Property-based testing.** Kiro checked display fidelity, clash completeness, orb bounds, public information and playback cancellation across seeded matches. In a controlled test of the clash property, Codex suppressed animations for defeated attackers in a copy. Seed 0 exposed two rendered attacks for three damage events. The unchanged presenter passed over seeds 0–99. [Property test](../tests/match/presenter.test.js) · [Controlled check](evidence/kiro-submission-preflight.md#clash-property-check)
8. **Powers.** Kiro activated the local Orb Duel Review Power to load the artifact review procedure. The Power directs the agent to the workspace MCP configuration for its verdict. Kiro used that setup to check both matching and stale artifacts. [Power and MCP evidence](evidence/kiro-overnight.md#power-and-mcp)
9. **Workflows.** The saved `orb-duel-replay` recipe runs verification in one step and assembles the receipt in another. The November 16 run on `2e63259` finished both steps with 104 passing Node tests and eight observed Chrome checks after a workspace-read approval. [Workflow recipe](../.kiro/workflows/orb-duel-replay.workflow.json) · [Run evidence](evidence/kiro-overnight.md#release-candidate-replay) · Summoning Circle also completed four steps for a stat proposal and for `review existing`. [Summoning Circle](evidence/kiro-card-pipeline.md#summoning-circle-workflow)
